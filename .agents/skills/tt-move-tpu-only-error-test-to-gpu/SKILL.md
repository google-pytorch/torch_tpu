# Move TPU-Only Error Test to GPU

This skill orchestrates the end-to-end migration of an error test from
`tests/tpu_errors_test.py` into `tests/errors_test.py`.

It triggers the `tt-analyze-tpu-only-error-test-to-gpu-movement` skill in a
sub-agent, evaluates the resulting report and outcome classification, takes
placement and cleanup action, delegates the test fix and cross-device
verification to a second sub-agent, and presents a structured summary to the
user.

## Input

*   `<TEST_NAME>` (required): Error test method name (e.g.,
    `test_jagged_offsets_not_int64`).
*   `<OUTPUT_DIR>` (optional): Directory shared across sub-agents for logs and
    reports. If omitted, defaults to `/tmp/tpu-only-test-analysis/<TEST_NAME>/`
    (outside the repository tree). Always resolve `<OUTPUT_DIR>` before spawning
    sub-agents and report the resolved path (and explicitly note when the
    default directory was used) to the user.

## Step-by-Step Workflow

### Step 1: Trigger Analysis in a New Sub-Agent

Resolve and create `<OUTPUT_DIR>` (never write inside the repository tree), read
[Analyze Sub-Agent Prompt Template](assets/analyze_subagent_prompt_template.md),
replace `<TEST_NAME>` and `<OUTPUT_DIR>`, and spawn a new sub-agent with the
resulting prompt.

Wait for the sub-agent to finish its execution. At that point, you should find:

-   A report at `<OUTPUT_DIR>/2-analysis.md` containing the analysis findings,
    outcome classification, and adapted test snippet
    (`## 3. Test Implementation`).
-   `tests/errors_test.py` remains unmodified if `<TEST_NAME>` came from
    `tests/tpu_errors_test.py` (the analysis sub-agent reverts its temporary
    Step 2 copy).

### Step 2: Follow Actions Based on Outcome and Diagnostic Case

Read `<OUTPUT_DIR>/2-analysis.md` generated by the analysis sub-agent and follow
the appropriate actions based on the outcome and diagnostic case:

#### If Outcome is "Not-Movable"

The test cannot be moved to `tests/errors_test.py` because PyTorch on CUDA
executes the operation with one of the following issues:

-   Without raising an exception (`NoExceptionRaised`)
-   Triggers an unrelated error check on GPU (`ExceptionMismatch`)
-   Crashes without reaching an error check condition (`Crash`).

**Instructions:**

1.  **Confirm Clean `errors_test.py`**: Verify `<TEST_NAME>` was not left behind
    in `tests/errors_test.py` (unless the test originally resided there).
2.  **Preserve Original Test**: Ensure `<TEST_NAME>` remains in
    `tests/tpu_errors_test.py`.
3.  **Update TPU-Only Rationale**: Ensure it has a descriptive
    `@et.why_tpu_only(...)` rationale based on the technical rationale in
    `<OUTPUT_DIR>/2-analysis.md`.
4.  **End Task**: Inform the user of the `Not-Movable` verdict, summarize the
    diagnostic case and technical rationale from the report, report the resolved
    `<OUTPUT_DIR>` path (noting if the default directory was used), and
    terminate the task.

#### If Outcome is "Movable"

The test can be moved to `tests/errors_test.py` because PyTorch on CUDA either:

-   Passes or matches the expected error (`Passing`)
-   Raises a related error or can be steered into the error check
    (`ExceptionMismatch`).
-   Crashes (out-of-bounds access) or can be steered into an error check
    (`Crash`).

If the diagnostic case from the analysis report is `Passing`:

1.  **Ensure Test Is in `errors_test.py`**: Check whether `<TEST_NAME>` is
    already in `tests/errors_test.py`. If not, insert the adapted test from
    `## 3. Test Implementation` of `<OUTPUT_DIR>/2-analysis.md` at the bottom of
    `TpuVsGpuErrorTest` in `tests/errors_test.py`, and confirm it passes on both
    TPU and GPU using `--test_filter="*<TEST_NAME>*"` and
    `--test_sharding_strategy=disabled`.
2.  **Delete Original Test**: Delete the entire `<TEST_NAME>` method (including
    any `@et.why_tpu_only` decorator) from `tests/tpu_errors_test.py`.
3.  **Proceed to Step 4**: Skip Step 3 and go directly to Step 4.

### Step 3: Apply Fix and Verify Both Platforms in a New Sub-Agent

For `ExceptionMismatch` or `Crash`, read
[Apply Fix Sub-Agent Prompt Template](assets/apply_fix_subagent_prompt_template.md)
and [Final Report Template](assets/final_report_template.md), replace
`<TEST_NAME>`, `<OUTPUT_DIR>`, and `<FINAL_REPORT_TEMPLATE>`, and spawn a new
sub-agent with the resulting prompt.

### Step 4: Read Report and Summarize to the User

*   Read the analysis report in `<OUTPUT_DIR>/2-analysis.md`.
*   If Step 3 ran (diagnostic case `ExceptionMismatch` or `Crash`), read the
    final report in `<OUTPUT_DIR>/4-final-report.md` (skip this for `Passing`,
    since Step 3 did not run).
*   Report the resolved `<OUTPUT_DIR>` path (noting if the default directory was
    used) and summarize the results to the user with the following exact
    structure:

1.  **Test Outcome**: State the test outcome (`Movable` or `Not-Movable`).
2.  **Diagnostic Case**: State the diagnostic case (`Passing`,
    `NoExceptionRaised`, `ExceptionMismatch`, or `Crash`).
3.  **Input Transformations Step Sequence**:
    *   If input adjustments were applied, list all of them. Each step should:
        *   Have an explanation under 80 characters.
        *   Have a small diff showing the actual code change.
    *   If no input adjustments were required: `None required (only error
        message/type adaptation in assert_raises_message)`.
4.  **Status**: `SUCCESS` or `FAILED`.
5.  **Failure Reason** (only if `FAILED` status): State what was expected, and
    what was actually observed.
6.  **Final Test Placement**: State whether the test resides in `errors_test.py`
    (with removal from `tpu_errors_test.py`) or remains in `tpu_errors_test.py`.
